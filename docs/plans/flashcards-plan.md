# Feature Plan: AI Flashcard Generation (Anki CSV Export)

Status: Draft — waiting for confirmation
Classification (per `CLAUDE.md`): **Large** (AI integration) — implementation starts only after
this plan is reviewed and explicitly confirmed.

## 1. Goal

Let a student turn an existing **Markdown note** (the `Note` domain) into a set of flashcards
generated by Claude via the Anthropic API, review and edit the cards in StudyHub, and download
them as a **CSV file that Anki can import directly**.

In line with `CLAUDE.md` ("AI Features"), the cards should help the student *learn* the material:
each card asks about one concept and the answer explains it. Cards are never "solutions" to
assignments or exams.

Decisions from review:

- **Source: only Markdown notes.** Uploaded documents (PDF/DOCX) are deliberately out of scope —
  writing your own notes first is the better learning workflow, and it keeps API cost small and
  predictable (a note is capped at 50,000 characters, see section 8).
- **Model: `claude-sonnet-5-5`** (the cheaper model is sufficient for this task).
- **Cards are always in German.**
- **No database persistence for now.** Generated cards live only in the page's state until they
  are exported. Persistence is kept in mind as a possible follow-up (see section 9).

## 2. Scope

In scope:

- Generate flashcards from exactly one Markdown `Note`.
- Cards are **always generated in German**, regardless of the note's language; technical terms
  may keep their established English name (e.g. "Hash Map", "Deadlock") where that is common
  usage.
- Options per generation: target number of cards (e.g. 5–50), optional focus hint (free text,
  e.g. "only the section on B-trees", "definitions").
- Preview the generated cards on the page, edit / delete single cards, regenerate.
- Download the (edited) cards as Anki-compatible CSV (`Front;Back;Tags`).
- Replace the "coming soon" placeholder on `/flashcards` with the real page.

Out of scope (later milestones):

- **Persisting decks/cards in the database** (see section 9).
- Studying / spaced repetition inside StudyHub (Anki does that).
- Direct `.apkg` export or AnkiConnect sync.
- Cloze cards, image cards (Basic front/back only for now).
- Generating from uploaded documents (PDF/DOCX) — excluded on purpose, see section 1.
- Generating from several notes at once, or from a whole course.
- Streaming the generation progress card-by-card into the UI.
- Usage/cost tracking dashboard.

## 3. Decisions

### 3.1 Claude API access

- **Official Anthropic C# SDK** (NuGet `Anthropic`), no hand-written HTTP client.
- **Model: `claude-sonnet-5-5`**, configurable via options (`Anthropic:Model`) so it can be
  switched (e.g. to `claude-opus-5-5`) without code changes.
- **Effort: `medium`** (set explicitly via `OutputConfig.Effort`; extracting and phrasing cards is
  not a hard reasoning task). Configurable (`Anthropic:Effort`).
- **Structured output** (`OutputConfig.Format` with a JSON schema) so the response is guaranteed to
  be `{ "cards": [ { "front": string, "back": string, "tags": string[] } ] }` — no fragile
  parsing of free text, no assistant prefill (not supported on current models).
- **Input:** the note's title and Markdown content as a plain text content block. No file
  parsing. Attached documents of a note are ignored.
- **Refusals / errors:** check `StopReason` (`refusal`, `max_tokens`) before reading content; map
  SDK exceptions (rate limit, 5xx, auth) to a `FlashcardGenerationFailedException` with an error
  code. Enable the server-side refusal fallback (`fallbacks: "default"`) as recommended for this
  model.
- **API key:** `ANTHROPIC_API_KEY` environment variable / user-secrets only — never in a committed
  `appsettings.json`. `docker-compose.yml` passes it through to `studyhub-api` only; the UI
  container never sees it. If no key is configured, the feature reports a clear
  "AI not configured" error instead of crashing at startup.
- **Prompt (system):** fixed, versioned in code; instructs Claude to
  - create atomic cards (one fact/concept per card), questions that require understanding,
    answers that briefly explain *why*;
  - stick strictly to the provided note (no invented facts), preserve technical correctness,
    keep code/formulas intact;
  - not produce solutions to assignments/exams contained in the material;
  - use HTML for formatting in answers (`<br>`, `<code>`, `<b>`), since Anki renders HTML;
  - return at most *N* cards, **always in German**, with 1–3 short tags.

### 3.2 No persistence (for now)

- Generation is **stateless on the server**: `POST generate` returns the cards, nothing is
  written to the database. No new entity, no repository, **no migration**.
- The generated cards live in the `/flashcards` page's component state (Blazor Server circuit).
  Editing and deleting cards only changes that state.
- **Export is stateless too:** the UI sends the current (possibly edited) cards to
  `POST export`, the Api builds the CSV and returns it; the CSV is never stored anywhere.
- Consequence: leaving or reloading the page discards unexported cards (and a new generation
  costs a new API call). The page warns about this (hint text near the export button).

### 3.3 Anki CSV format

Anki (2.1.54+) understands header lines in imported text files, so the export needs no manual
field mapping in the import dialog:

```
#separator:Semicolon
#html:true
#notetype:Basic
#deck:StudyHub::<Course or semester name>::<Note title>
#tags column:3
Front;Back;Tags
"Welche Annahme trifft Dijkstra über Kantengewichte?";"Alle Gewichte sind nicht negativ.<br>Eine negative Kante könnte eine bereits finalisierte Distanz nachträglich verkürzen.";dijkstra graphen
```

- UTF-8 (written without BOM; Anki handles umlauts correctly).
- Every field quoted; `"` escaped as `""`; line breaks converted to `<br>`.
- Tags: space-separated, spaces inside a tag replaced by `_`.
- Deck name: built by the Api on generation from the note's course (or semester) and title, and
  passed back by the UI on export.
- File name: `<note-title>.csv` (sanitized).

## 4. Architecture Impact

End-to-end flow (same as every other domain):
`Flashcards.razor` → `IFlashcardAccessor` (Logic.Integration) → `FlashcardController` (Api) →
`FlashcardOrchestrator` (Business) → `INoteRepository` / `ICourseRepository` /
`ISemesterRepository` (Data, existing) + `IFlashcardValidator` / `IAnkiCsvSerializer` (Domain) +
**`IFlashcardGenerator`** (`StudyHub.Logic.Integration`, Claude).

| Layer / project | New types |
| --- | --- |
| `StudyHub.Shared/Flashcards/` | `FlashcardDto` (`Front`, `Back`, `Tags`), `FlashcardSetDto` (`NoteId`, `DeckName`, `FileName`, `Cards`), `GenerateFlashcardsRequest` (`NoteId`, `CardCount`, `FocusHint`), `ExportFlashcardsRequest` (`DeckName`, `FileName`, `Cards`), `FlashcardErrorCodes`, `FlashcardValidationException`, `FlashcardGenerationFailedException`, `AiNotConfiguredException` |
| `StudyHub.Shared/Configuration/` | `AnthropicOptions` (Model, Effort, MaxTokens, MaxCards) |
| `StudyHub.Logic.Domain.Contract` | `IFlashcardValidator`, `IAnkiCsvSerializer` |
| `StudyHub.Logic.Domain` | `FlashcardValidator` (front/back required + max length, tag length, card count 1–50), `AnkiCsvSerializer` (pure, escaping rules above) |
| `StudyHub.Logic.Integration/Ai/` | **All AI integration logic lives in `StudyHub.Logic.Integration.csproj`** (not in `Logic.Integration.Contract`): `IFlashcardGenerator` (input: note title + Markdown + options; output: `IReadOnlyList<FlashcardDto>`), `ClaudeFlashcardGenerator` (Anthropic SDK, prompt, JSON schema, error mapping), `AddStudyHubAi(IConfiguration)` registration (called from the **Api** composition root only) |
| `StudyHub.Logic.Integration/Flashcards/` | `IFlashcardAccessor` / `FlashcardAccessor` (UI → Api: `GenerateAsync`, `ExportAsync`; longer `HttpClient.Timeout`, e.g. 3 min) |
| `StudyHub.Logic.Business.Contract` | `IFlashcardOrchestrator` (`GenerateAsync`, `ExportAsync`) |
| `StudyHub.Logic.Business` | `FlashcardOrchestrator`: loads the note via `INoteRepository`, rejects archived/missing/empty notes, resolves the course/semester name for the deck name, calls `IFlashcardGenerator`, validates the result, returns `FlashcardSetDto`; on export validates the cards and serializes them via `IAnkiCsvSerializer` |
| `StudyHub.Api/Flashcards/` | `FlashcardController`, `FlashcardExceptionHandler` |
| `StudyHub.UI` | `Flashcards.razor(.cs)` (note picker + options, card preview table with inline edit/delete, export button), `Services/FileDownloadAccessor` (+ interface, small JS-interop helper that hands the CSV bytes to the browser as a download — needed because the cards only exist in the circuit, so the GET-proxy pattern of `DocumentDownloadEndpoints` doesn't fit) |

### API endpoints (`api/flashcards`)

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | `generate` | `GenerateFlashcardsRequest` → `FlashcardSetDto` (nothing is stored) |
| `POST` | `export` | `ExportFlashcardsRequest` → Anki CSV (`text/csv`, file download) |

### Dependency notes

- `Logic.Business` already references `Logic.Integration` and uses `IFlashcardGenerator` from
  there — no new project reference needed. `Logic.Integration` keeps referencing only `Shared`
  (plus the new NuGet package). LAY-7 stays intact: Integration still never references
  Business/Domain.
- The Anthropic SDK package is only referenced by `Logic.Integration`. The UI also references
  `Logic.Integration` (for accessors) but never registers/uses the AI generator.

## 5. Database Impact

**None.** No new tables, no migration. Existing `Notes`/`Courses`/`Semesters` are only read.

## 7. Validation Plan

- `dotnet build` without new warnings, `dotnet test` green.
- Unit tests (xUnit + Moq), **no real API calls in tests**:
  - `AnkiCsvSerializer`: quoting, `""` escaping, semicolons/newlines in fields, tags with spaces,
    header lines, umlauts (UTF-8).
  - `FlashcardValidator`: required fields, max lengths, card count limits.
  - `FlashcardOrchestrator`: archived/missing/empty note, deck name from course vs. semester,
    generator failure propagation, invalid generator output, export of edited cards.
  - `ClaudeFlashcardGenerator`: response → `FlashcardDto` mapping and stop-reason handling,
    tested against a fake/stubbed response (mapping kept in a separately testable method).
- Api tests (`WebApplicationFactory`) with a fake `IFlashcardGenerator`: generate, export content
  type/body, 404/400 problem details, "AI not configured" response.
- Manual: generate cards from a real note, edit one card, export, import the CSV into Anki desktop
  and check fields, HTML rendering, umlauts, tags, and deck name.

## 8. Risks / Assumptions / Open Questions

- **Cost:** each generation is a paid API call. Because only notes are allowed (max 50,000
  characters ≈ 12–15k tokens), cost per generation is bounded (estimate, not measured): with the
  chosen `claude-sonnet-5-5` ($2 input / $10 output per 1M tokens) typically ~0.03–0.05 $, worst
  case (full-length note, 50 cards) ~0.12 $ — about half of what `claude-opus-5-5` would cost.
  Mitigations: card-count cap, effort `medium`, model configurable, no automatic regeneration.
- **No persistence:** cards that are not exported are lost on page reload, navigation, or a
  dropped Blazor circuit; regenerating costs another API call. Accepted for the first version.
- **Latency:** generation can take up to a minute → long accessor timeout + spinner; Blazor Server
  circuit stays alive meanwhile. Streaming is a later improvement.
- **Quality:** AI cards can be wrong. Cards are always editable before export and the prompt binds
  Claude to the source note.
- **Privacy:** note content is sent to Anthropic. The page shows a short hint.
- **Documentation inconsistencies found while planning** (to be clarified, not guessed):
  1. `CLAUDE.md` says Integration contains "AI Providers", but its Entity Framework section reserves
     `Infrastructure` for "AI provider adapters". This plan follows the Integration placement
     (also what `docs/agent-context.md` names as the intended home).
  2. `CLAUDE.md` / `docs/agent-context.md` describe `Contracts/` subfolders, entities in
     `Logic.Domain` and repository contracts in `Logic.Domain`; the code actually uses separate
     `*.Contract` projects (`Logic.Domain.Contract`, `Logic.Business.Contract`,
     `Data.Contract`, `Logic.Integration.Contract`), entity records in `Shared`, and `*Lifecycle`
     domain services. This plan follows the **current code**; the docs should be updated
     separately. Exception (per review): the AI integration contract `IFlashcardGenerator` lives
     in `StudyHub.Logic.Integration` itself, not in `Logic.Integration.Contract`.
- **Open questions:** none at the moment.

## 9. Follow-up: Persistence (kept in mind, not part of this feature)

If unexported cards getting lost turns out to be a problem, a later feature can add persistence
without changing the generation/export flow:

- New aggregate `FlashcardDeck` (`Id`, `Title`, `NoteId` FK → `Notes` with `Restrict`, `Model`,
  `IsArchived`, `CreatedAt`, `UpdatedAt`) with child `Flashcard` rows (`DeckId` FK with
  `Cascade`, `Front`, `Back`, `Tags`, `Position`); one migration `AddFlashcards`.
- Only the structured cards would be stored — **the CSV would still be generated on every
  export**, never stored.
- `FlashcardDto`/`AnkiCsvSerializer`/`IFlashcardGenerator` stay as they are; the orchestrator
  gains save/list/archive methods, and the page gains a deck list.
